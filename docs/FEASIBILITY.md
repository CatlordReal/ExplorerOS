# iPhone integration feasibility

| Capability | Roles and feasibility | Boundary |
|---|---|---|
| Notifications | iPhone ANCS Notification Provider/GATT server; Glass Notification Consumer/GATT client. Yes if Glass Bluetooth stack supports authenticated LE GATT. | Glass firmware/stack handles pairing, Service Changed, Notification Source, Control Point/Data Source fragmentation; app displays session-only data. |
| Media | iPhone AMS Media Service/GATT server; Glass Media Remote/GATT client. Yes. | Implement AMS Remote Command/Entity Update/Entity Attribute in stack/app; service can disappear. |
| Custom companion BLE | iPhone `CBCentralManager`/`CBPeripheralManager`. Qualified. | Background advertising/scanning are constrained; restoration does not survive user force-quit. No always-on guarantee. |
| Siri | iPhone HFP Audio Gateway; Glass HFP Hands-Free. `AT+BRSF` voice-recognition bit 3, `AT+BVRA=1`, SCO, then `AT+BVRA=0`. Hardware feasible. | Requires Classic HFP HF + SCO mic/speaker in Glass firmware. Android 4.4 public app APIs do not provide this system role. No public global Siri transcript/result API. |
| Calls/media keys | HFP call controls; AVRCP Controller on Glass and Target on iPhone. HID consumer keys fallback only. | Firmware/stack work; ANCS actions only when iOS advertises them. iOS apps cannot generally control Phone.app calls. |
| Directions | iPhone companion uses `MKDirections`/`MKRoute.Step.instructions`, relays route steps; or launches Maps. | Own Glass navigation needs location/network/rerouting. Apple Maps owns navigation when launched. |
| Qt | Current Qt 6 starts at Android 9/API 28. XE24 is Android 4.4/API 19. | Historical Qt 5 may build but is obsolete and needs device/toolchain validation. Prefer native Java/JNI for Bluetooth system work. |
